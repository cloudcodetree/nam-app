## What shipped

**Item 1 — `Stack.uid`.** `nam::Stack` (`Source/model/StackModel.h`) gained
a stable `uid` ("s1","s2"... unique within the file), minted by
`StackModel::parse` for any stack that lacks one (v1 migration and
pre-uid v2 files alike, via a shared `assignMissingStackUids` pass) and by
the new `StackModel::nextStackUid(stackList_)` at every creation site
(`AppShellStacks.cpp`'s `wiz.onSave`, which both `doSave` and
`pickTemplate` funnel through). Every async `(index,name)` revalidation
that guarded against a stack being removed/renamed/reused mid-flight was
replaced with `(index bounds, uid)`: the gear-picker fetch capture
(`AppShellStacks.cpp`) and `PendingToneApply`/`finishToneLoad`/
`drainPendingToneApply`/`startToneLoad` (`AppShellPerform.cpp`). TDD:
failing tests landed first in `tests/test_stack_model.cpp`.

**Item 2 — `stacks.json.bak` safety net.** `AppShell::loadStacksState`
backs up the raw file (via a new `BrowseServices::backupStacksJson` hook,
implemented at the host layer as `AndroidAudioApp::backupStacksJson()` in
`AndroidToneServices.cpp`, wired with one line in `AndroidAudioApp.cpp`)
exactly when `StackModel::parse` couldn't make sense of non-empty raw
content. Round-1 review caught a MAJOR: the original trigger
(`stackList_.empty() && raw.isNotEmpty()`) couldn't distinguish "parse
failed" from "parse succeeded on a legitimately empty file" — fixed with
new `StackModel::looksLikeStacksFile` (shape-only check).

**Item 3 — `performApplyInFlight_` watchdog.** New `AppShell::ApplyTimeout`
interface + `ApplyTimeoutImpl` (`AppShellPerform.cpp`), same owner-backed
one-shot-`juce::Timer`-behind-`arm()`/`cancel()` shape as
`AndroidBilling::PurchaseTimeout`. `startToneLoad`'s network route arms a
30s timer; on fire, `handleApplyTimeout` resolves the attempt through the
same `finishToneLoad` failure path (toast + revert + drain pendings) a
real failed callback takes. Race-safe via a `performApplyGen_` generation
counter — whichever of the timeout or the real callback runs first wins,
the loser is a no-op.

**Item 4 — `dismissPaywall()` factoring.** New `AppShell::dismissPaywall()`
(setVisible(false) + the nav-hidden re-derive `show()` already does)
replaces three divergent inline blocks (`onClose`, `handleBackButton`,
`refreshProState`) — only `onClose` did the nav re-derive before.
Net +9 lines on `AppShell.cpp` (already over the 800-line no-growth cap);
the reviewer accepted this as the dedup the rule exists to encourage, not
a feature inlined into a god file.

**Follow-up — review round 1.** Fixed the MAJOR above plus two MINOR uid-
safety findings: `maxStackUidIndex` signed-overflow (UB) on a hand-edited
`"s2147483647"` uid, capped at a 1e9 ceiling; `assignMissingStackUids`
now re-mints hand-edited duplicate uids past the first occurrence. TDD:
three new failing tests first.

**Follow-up — docs.** `docs/wiki/decisions.md` dated entry recording the
whole batch, the findings, the fixes, and the residual MINOR gaps judged
not worth chasing (all require deliberately hand-edited boundary-value
uids in the 999,999,999–1,000,000,000 range — a billion-stack file).

## Concerns / residual risk

1. **Item 3 has no device-level proof of the actual 30s-unwedge behavior**
   — only code review + full compile/link. If this matters before public
   launch, worth a dedicated pass: airplane-mode the emulator, trigger a
   scene tap against a non-local toneId, and either wait the real 30s or
   temporarily drop the constant to something short (5s) for one manual
   run, reverting before any commit.
2. **Two MINOR findings remain unfixed by design** (documented in
   decisions.md): a duplicate-uid re-mint at the exact 1e9 cap boundary
   isn't re-checked against already-seen uids, and `nextStackUid` can
   mint a uid colliding with an existing cap-excluded one at that same
   boundary. Both require a hand-edited file with uids in the high
   9-digit range — not reachable through any in-app flow.
3. **One MINOR trade accepted**: `looksLikeStacksFile`'s shape-only check
   narrows the backup net for the (implausible) case of a top-level-valid
   v2 file where every single stack entry is individually fatal to parse
   — that content is now overwritten without a `.bak` where the
   pre-review-round-1 code would have (wrongly) backed it up. Judged
   acceptable since organic corruption (truncation, a future version
   bump) still triggers the backup correctly.
4. **`AndroidAudioApp.cpp` grew by 1 net line** (802 → 803) to wire
   `backupStacksJson` — it was already over the 800-line no-growth cap.
   Flagged in the item-2 commit message as a deliberate, minimal exception
   (a single unavoidable plumbing line, not a feature inlined wholesale);
   no reviewer finding was raised against it.
