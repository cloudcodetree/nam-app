# Stacks Phase A UX-correctness batch — report (scratch, not committed)

Date: 2026-08-15

## Scope

Five open items from the Phase A pre-launch checklist (docs/wiki/decisions.md,
2026-08-15 "STILL OPEN" list). All landed in one commit (stayed small/cohesive;
the wizard-nav item turned out to be a 1-line fix, not a split-worthy change).

## Item 1 — amp stomp tap

`Source/app/ui/AppShellPerform.cpp`: `wirePerformView()`'s `perf.onStompTap`
now looks up the tapped uid's chain item; if `type == GearType::Amp` it calls
`applyAmpCycle(idx)` instead of the bypass mutation. Pedal/post unchanged
(still `mutateItem(... bypassed = !bypassed)`).

**Bonus finding while E2E-verifying this item**: the STOMP grid's own
sub-label for an amp-mapped switch was reading `ChainItem::title` (the
item's static title, set once at Add/Swap time) instead of the active
channel's title — so even after routing to `applyAmpCycle`, the switch's
face text never visibly changed on tap, even though the load/cycle was
firing correctly underneath. Fixed in `StackPerformViewPaint.cpp`'s
`paintCell` (CellKind::Stomp branch): an amp item now shows
`it->channels[it->activeChannel].title`, same source the SCENES-mode AMP
cell already uses, and the LED just stays lit (no bypass concept applies).
This was in scope because the task's own E2E ask for item 1 was "verify the
amp title ... changes" — without this fix that check would have failed.

## Item 2 — FS pills on Cab sheet

`Source/app/ui/StackItemSheet.cpp`: `layout()` skips the whole FOOTSWITCH
row (label + 9 pills) when `item_.type == GearType::Cab`, clearing
`fsLabelRect_`/`fsPillRects_` to empty so `paint()` and `mouseUp()` (both
now guarded on `!fsLabelRect_.isEmpty()`) skip it too. `y`/`contentH_` only
advance inside the `!isCab` branch, so the sheet is shorter for a Cab
(scrollbar math updates automatically via the existing `contentH_`-driven
clamp). Pedal/Amp/Post unchanged.

## Item 3 — mismatched-tab picker feedback

Preferred approach taken (extend the disabled-tab treatment), not the
toast fallback — it reuses the exact same visual language Add mode's
"one amp per stack for now" already established.

`StackGearPicker::open()` signature changed from
`(GearType initialTab, bool ampDisabled, bool cabDisabled)` to
`(GearType initialTab, std::array<bool,4> disabledTabs, juce::String hint)` —
generalizes from "two hardcoded reasons" to "any subset of tabs, with an
owner-supplied explanation." `AppShellStacks.cpp`'s `openGearPicker` now
builds that array per mode:
- Add: unchanged behavior (canAdd-gated Amp/Cab), hint "one amp per stack
  for now".
- AddChannel: only Amp enabled, hint "pick an amp capture for this
  channel".
- Swap: only the target item's own type enabled, hint "swap must stay the
  same gear type".

`applyGearPick`'s existing early-returns for a mismatched tab stay in place
as defense in depth (now unreachable in practice since the picker can't
produce a mismatched pick anymore, but cheap to keep).

Only one call site (`StackDetailScreen::picker()`), no test references —
verified via grep before changing the signature.

## Item 4 — orphan failure toast

`AppShellPerform.cpp`'s `finishToneLoad`: the `else` branch (load failed)
used to run `onFail()` gated on `stillValid` but the toast unconditionally.
Restructured to `else if (stillValid) { onFail(); toast; }` — both now share
the same gate. `saveStacksState()`/`pushStacks()` below were already
`stillValid`-gated; this just brings the toast in line with them.

## Item 5 — wizard nav policy

**Chose option (b): close (discard) the wizard when a nav button navigates
away**, not (a) hide the nav while the wizard is open.

Why: (a) would need `setNavHidden` wired at 3+ separate call sites —
`wireCreateWizard`'s onCreate (wizard.open()), the wizard's own onCancel
(its internal back-chevron closes independently of hardware back), and
`handleBackButton`'s existing `closeWizard()` branch — spread across
`AppShellStacks.cpp` and `AppShell.cpp`, mirroring exactly the kind of
scattered-restore-call bug the paywall's `dismissPaywall()` unification
fixed earlier in the project (decisions.md, hardening batch). It would also
be visually inconsistent: PERFORM's nav-hidden is a deliberate full-bleed
*stage view*; the wizard is a modal *form flow* layered over Home, closer in
spirit to the paywall (which forces nav visible, not hidden).

(b) is one line: `AppShell::show(Screen s)` already runs a handful of
"leaving the old state cleanly" steps at its top (`closeIoPanel()`,
`closeMoreMenu()`, paywall dismiss) before switching `current_` — added
`if (s != Screen::Stacks && stacksHome_ != nullptr) stacksHome_->closeWizard();`
to that list, reusing the exact same `closeWizard()` the hardware-back path
already calls. Since `show()` is the single choke point every nav button
(BROWSE/FAVORITES/MORE→Downloaded, the nav-bar fallback tap, STACKS itself)
routes through, this covers all of them uniformly with no new state and no
new call sites — least invasive to `AppShell.cpp`, and it makes hardware
back and every nav button agree on the exact same policy (discard),
instead of introducing a second policy (hide) that back doesn't share.

Added a dated decisions.md line recording this choice and rationale.

## Review round 1 (adversarial, post-push)

First push got VERDICT: PASS (no BLOCKER) but surfaced two real MAJORs and
two MINORs worth fixing before calling this done — fixed in a follow-up
commit, same day:

- **MAJOR**: `applyAmpCycle`'s modulo is a no-op at `channels.size()==1`,
  so a switch mapped to a single-channel amp went from "toggles a
  meaningless LED" (old behavior) to "does visibly nothing at all" (new
  behavior) — worse, not better, for that one case, plus a wasted
  `stacks.json` write per tap. Fixed: `onStompTap` toasts "only one
  channel — add more in EDIT" instead of calling `applyAmpCycle` when
  `channels.size() <= 1`. Verified on-device: `My Rig` (uid s1) has a
  1-channel amp on FS7 — tapping it now shows the toast instead of
  silently doing nothing.
- **MAJOR**: gating the failure toast on `stillValid` (this batch's own
  item-4 fix) shares that predicate with `onFail`/save/push, which is
  deliberately strict (index AND uid match at that exact index, since
  those three touch `stackList_[stackIdx]` directly and an unrelated
  earlier-stack removal can shift a DIFFERENT stack onto that index).
  Sharing it meant a stack that merely shifted position also lost its
  failure toast, not just one that was actually removed. Fixed: added a
  looser `stillExists` (uid found anywhere in `stackList_`, regardless of
  index) that gates the toast alone; `stillValid` still gates
  onFail/save/push unchanged.
- **MINOR**: Add-mode picker hint said "one amp per stack for now" even
  when only the CAB tab was actually dimmed. Fixed: now names whichever
  of amp/cab/both are disabled.
- **MINOR**: STOMP cell's amp sub-label painted blank for an amp with an
  empty `channels` array (unreachable via any in-app flow today — every
  producer seeds `channels[0]`). Fixed: falls back to the item's own
  title.
- **MINOR, deliberately left unfixed**: a Cab item's `fs` isn't zeroed on
  load, so a hand-edited stacks.json with a stale nonzero cab `fs` still
  occupies a STOMP slot with no sheet control left to clear it. Reviewer
  confirmed no in-app flow can produce this today; noted in decisions.md
  rather than given its own `StackModel::parse` migration step.

Re-verified after the round-1 fixes: clang-format clean, headless suite
green (379417/121), Android build clean, and two targeted on-device
re-checks (Stack 10's 3-channel amp still cycles + loads correctly on
FS1 tap; `My Rig`'s 1-channel amp now toasts instead of doing nothing on
FS7 tap).

## Review round 2 (adversarial, post-push, same day)

Second push also got VERDICT: PASS (no BLOCKER), but re-examined round 1's
"cab fs not zeroed, deliberately unfixed" MINOR and correctly called it out
as a MAJOR data-migration bug, not a UI-only gap:

- **MAJOR (escalated from round 1's deferred MINOR)**: a stacks.json
  written by the build BEFORE this batch (when the item sheet still
  offered FS pills on a Cab) can already have `{"type":"cab","fs":4}` on
  a real device. My round-1 reasoning ("no in-app flow can produce this
  today") was true looking forward but ignored that old files already
  exist. Fixed properly this time: TDD (failing test first in
  `tests/test_stack_model.cpp` -- confirmed red, `4 == 0` assertion
  failure, before touching source), then `StackModel::itemFromJson` zeroes
  `fs` for any `GearType::Cab` on parse. This is the correct fix location
  per CLAUDE.md's own reasoning the reviewer echoed: parse() is the one
  choke point every persisted file (v1 or v2, in-app-written or
  hand-edited) flows through, so fixing it there closes the gap
  completely instead of leaving it UI-reachability-dependent.
- **MINOR**: `onStompTap`'s `channels.size() <= 1` guard checks the
  TAPPED amp, but `applyAmpCycle` cycles the FIRST amp in the chain --
  divergent only in a hand-edited/future file with 2+ amps (`canAdd` caps
  Add at one today, so not reachable in-app). Fixed anyway since it was
  cheap and directly adjacent to this batch's own new code:
  `applyAmpCycle(stackIdx, targetUid = {})` -- empty still means "first
  amp" (unchanged for the SCENES-mode AMP cell's `onAmpCycle`), STOMP now
  passes the tapped item's own uid.
- **MINOR, left as-is**: toast/no-revert mismatch when scene-load fails
  after an unrelated EARLIER stack was removed mid-flight (stillValid
  goes false so onFail/revert is skipped, but stillExists is true so the
  toast still fires) -- reviewer confirmed this exact mismatch shape
  already existed at the pre-batch baseline (unconditional toast), so
  this batch didn't introduce it, just narrowed when it's visible.
- **MINOR, left as-is**: the nav bar's few px of dead space beside the
  orb (not a labeled button) falls through to the pre-existing
  `if (navBar_.contains(p) && current_ != play_) show(Screen::Play)`
  fallback, which now also silently discards an open wizard (no confirm)
  as a side effect of item 5's chosen policy. The fallback itself
  predates this batch; a real fix (confirm-before-discard, or excluding
  dead space from the fallback) is a larger UX decision than this batch's
  scope.

TDD note: the StackModel fix is the only change in this whole batch that
touches `Source/model` (JUCE-free core, TDD-mandatory per CLAUDE.md) --
confirmed the new test failed first, then made it pass, in the same commit.
