## Concerns / follow-ups for Chris

1. **Tracked, not fixed (deliberately, per the review's own read)**:
   `elide()` re-measures text via `GlyphArrangement::getStringWidth` on
   every repaint rather than caching the elided string alongside the pill
   width computed in `layout()`. Bounded today (a handful of labels, not a
   hot list) but worth caching if a Stacks screen ever lists something
   large.
2. **Three MINOR findings from the final round, left open**: routing pills
   are `.expanded(2)` while FREEFORM is `.expanded(4)` (a ~4px asymmetric
   dead band between them, not a real-world miss given the ~15px gap
   measured on device); `freeformToggleRect_`/`routingPillRects_` hit
   tests lack the `!isEmpty()` guard every other rect in the file has
   (matters only in a degenerate near-zero-height layout, not reachable on
   any real device size); the JUCE `expanded()`-outside-bounds gotcha
   discovered in round 3 is recorded in a source comment but not yet in
   `docs/wiki/ui-system.md` (the neighboring empty-rect gotcha already
   lives there, obvious next entry).
3. **Pre-existing, not a regression**: the "START EMPTY -- BUILD STEP BY
   STEP" wizard button's tap target sits correctly per the code (confirmed
   via computed coordinates once the nav-bar height/contentBounds math was
   worked out) -- my early failed taps were coordinate-estimation error on
   my part reading the screenshots, not an app bug. No fix needed; noting
   only because it cost real time to rule out.
4. Chris should look at `DONE-03-perform.png` and judge whether the tall
   4-cell single-row SCENES grid (cellH capped at 148px) is the right
   feel for a light setlist, or whether he'd rather see 2 rows with more
   headroom above/below instead of 1 very tall row -- this was a judgment
   call within the "big touch targets" brief and there's a legitimate
   alternate reading.
