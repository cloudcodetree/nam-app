# TONE3000 integration

## API facts (verified against the live service)

- All endpoints need `Bearer` auth. OAuth2 + PKCE public client; ONLY the
  publishable key (`t3k_pub_`, CMake-injected from `.env`) is embedded. The
  client secret (`t3k_cs_`) must never be read, compiled, or logged.
- Loopback redirect `127.0.0.1:49222` needs CORS + Private-Network-Access
  headers and a listener that survives multiple connections (browser
  preflight + fetch + hard-nav). Tokens/codes/verifiers never in logs.
- `/api/v1/tones/search`: page/page_size (25), `sort`
  trending|newest|oldest|best-match|downloads-all-time, `gears`
  amp-cab|amp|cab|pedal|outboard|space|experimental ("_"-joined multi),
  `format` nam|ir, `tags`, `makes`, `architecture` (int: 2=A2). NO
  streaming/SSE — "all results" means fetching pages on demand (the app
  appends as the user nears the deck end, capped at `kBrowseDeckCap`).
- `/api/v1/models?tone_id=X&architecture=2` — without the int architecture
  param the API returns the legacy (A1) list. Real ids are JSON integers;
  parsers must be type-tolerant. `model_url` 302s cross-host: drop the
  Bearer on the hop.

## Local semantics

- **Heart** = download + import to library + `favorite` flag. **Download
  button** = save only (import, flag untouched). Un-heart keeps the file;
  un-save removes it. One library list; the flag splits the decks.
- Cache files: `keep_<id>.nam` (models), `ir_<id>.nam` (IR wavs), pruned.
  API-supplied ids are charset-whitelisted before becoming paths.
- IR imports carry the tone title as displayName (WAVs have no metadata;
  pre-fix "ir_123" names heal on the next heart-toggle).
- Artwork: `images[]` → cached per tone as jpg (≤700px, pruned to 64),
  digit-only id + https + 8MB bounds. Deck thumbnails: 160px, bounded cache.
- Sessions are EXPENSIVE: destroying `Tone3000Session` joins download
  threads (up to 20 s) — reuse unless the token changed, never rebuild per
  call, and never funnel two dependent downloads concurrently (they share
  one thread; the second supersedes the first — stack loads are sequential).
